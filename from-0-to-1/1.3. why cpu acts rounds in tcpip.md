# 为什么 TCP/IP 需要很多次 CPU 的介入？

TCP/IP 需要多次 CPU 介入，根本原因在于**传统协议栈的软件实现方式**：数据从应用程序到网卡，要经过用户态与内核态切换、多次内存拷贝、逐层协议处理，这些环节都依赖 CPU 执行指令来完成。

## 具体来看，CPU 介入主要发生在以下几个环节：

1. **系统调用与用户态/内核态切换**
   应用程序调用 `send()` 等 socket API 时，CPU 需要从用户态陷入内核态，执行系统调用处理程序。这个上下文切换本身就有开销，数据量大或调用频繁时累积明显。

2. **多次内存拷贝**
   传统路径中，数据通常要经历：应用程序缓冲区 → 内核 socket 缓冲区 → 协议栈处理 → 网卡驱动缓冲区 → 网卡。每一次拷贝都是 CPU 执行的 `memcpy` 类操作，数据越大、拷贝次数越多，CPU 消耗越高。

3. **逐层协议处理**
   TCP 层要计算校验和、管理序号和确认、处理重传与拥塞控制；IP 层要查路由表、做分片重组；链路层要封装帧、计算 CRC 等。这些逻辑都由内核协议栈的软件代码执行，全部占用 CPU 周期。

4. **中断处理与轮询**
   网卡收到数据后通过中断通知 CPU，CPU 要执行中断处理程序，把数据从网卡缓冲区搬到内核，再唤醒等待的进程。高吞吐场景下中断频繁，CPU 大量时间花在中断处理上。

5. **协议栈的通用性开销**
   内核协议栈要兼容各种场景，代码路径长、分支多，不像专用硬件那样可以针对固定流程做流水线优化，因此单位数据的处理成本更高。

## 这正是 RDMA 要解决的问题

RDMA 通过**内核旁路**（应用直接与网卡交互，省去系统调用和上下文切换）、**零拷贝**（网卡直接读写应用内存，省去多次内存搬运）、**CPU 卸载**（协议处理由网卡硬件完成）三项技术，把上述 CPU 介入环节大幅削减，从而释放 CPU 算力、降低延迟。这也是为什么在高性能计算、AI 训练、分布式存储等场景中，RDMA 相比传统 TCP/IP 有明显优势。
