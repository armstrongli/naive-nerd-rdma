# 什么是 DMA？

DMA（Direct Memory Access，直接内存访问）是一种让**外部设备直接与内存交换数据，而无需 CPU 逐字节参与搬运**的硬件机制。它的核心价值是把 CPU 从繁琐的数据搬运工作中解放出来，让 CPU 专注于计算和控制。

## 为什么需要 DMA？

在没有 DMA 的时代，外设（如网卡、磁盘）与内存之间的数据传输需要 CPU 全程介入：CPU 要不断读取外设数据、写入内存，或者反过来。这种方式有两个问题：

- **浪费 CPU 算力**：CPU 大量时间花在简单的数据搬运上，无法做更有价值的计算。
- **速度受限**：CPU 搬运数据的速率受指令执行节奏限制，难以匹配高速外设的吞吐需求。

DMA 的出现就是为了解决这个问题：由专门的 DMA 控制器（DMAC）代替 CPU 完成数据搬运。

## DMA 的工作流程（以网卡接收数据为例）

1. **配置**：CPU 向 DMA 控制器写入源地址（如网卡缓冲区）、目的地址（如内存缓冲区）、传输长度等信息，然后启动 DMA 传输。
2. **搬运**：DMA 控制器接管总线，直接在网卡缓冲区和内存之间搬运数据，全程不经过 CPU。
3. **完成通知**：数据搬运完毕后，DMA 控制器通过中断通知 CPU“数据已就绪”，CPU 再去处理这些数据。

整个过程 CPU 只需在开始和结束时各介入一次，中间的搬运工作全部由 DMA 硬件完成。

## DMA 与 RDMA 的关系

两者容易混淆，但层级不同：

- **DMA** 是**单机内部**的机制，解决的是本机外设与内存之间的数据搬运问题。
- **RDMA** 是**跨网络**的机制，解决的是两台计算机之间直接读写对方内存的问题。RDMA 的网卡内部同样依赖 DMA 技术来实现“零拷贝”——网卡通过 DMA 直接读写应用程序内存，无需 CPU 搬运。

可以理解为：DMA 是底层硬件能力，RDMA 是在网络场景下对这类能力的延伸和组合。传统 TCP/IP 路径中，网卡与内存之间其实也用到 DMA，但数据还要经过内核协议栈的多次拷贝和 CPU 处理；RDMA 则把“内核旁路 + 零拷贝 + CPU 卸载”结合在一起，把 DMA 的优势发挥到了网络传输层面。

# DMA 接收数据的实际案例：从网卡到内存

下面用“一台服务器通过网线收到一个以太网帧，最终写入某进程的内存缓冲区”这个具体场景，把 DMA 接收数据的过程拆开来看。为了具体，假设使用一块支持 DMA 的千兆/万兆网卡，操作系统是 Linux，接收的是一个普通的 TCP 数据包。

## 场景设定

- 网卡通过 PCIe 总线插在服务器上，网卡内部有自己的接收缓冲区（RX FIFO/片上内存）。
- 内存中有一块由网卡驱动预先分配好的**接收缓冲区**（DMA 缓冲区），它的物理地址已经被写入网卡的接收描述符环（RX Ring）。
- CPU 运行着网卡驱动和上层协议栈。

## 实际执行过程

### 1. 驱动初始化时预先分配 DMA 缓冲区并告知网卡

网卡驱动在启动时，会在内存中分配一批接收缓冲区（比如每个 2KB），并把每个缓冲区的**物理地址**、长度等信息写入内存中的**接收描述符环**（RX Descriptor Ring）。然后驱动把这些描述符环的基地址告诉网卡（通过写网卡的寄存器）。此后网卡就知道：“收到数据后，往这些内存地址里放。”

### 2. 网卡收到帧，硬件自动发起 DMA 写

网线传来电信号，网卡的 PHY/MAC 芯片解析出以太网帧，校验 CRC 通过后，帧数据进入网卡内部缓冲区。此时网卡硬件**不需要 CPU 参与**，自动做两件事：

- 从接收描述符环中取出下一个可用的描述符，得到目标内存的物理地址；
- 发起 PCIe 总线上的 DMA 写事务（DMA Write），把帧数据直接写入该物理地址对应的内存区域。这一步是网卡作为总线主设备（Bus Master）直接读写内存，CPU 完全不介入数据搬运。

### 3. DMA 完成后，网卡更新描述符并触发中断

数据写完后，网卡硬件会更新描述符的状态位（标记“此缓冲区已有数据”），然后向 CPU 发送一个**中断**（或通过 NAPI 的轮询机制被驱动感知）。中断信号到达 CPU 后，CPU 暂停当前工作，跳转到网卡驱动注册的中断处理程序。

### 4. CPU 在中断处理中做“收尾”工作

CPU 此时介入，但只做少量控制性工作，不做大数据搬运：

- 驱动读取描述符状态，确认哪些缓冲区收到了数据；
- 为这些缓冲区建立 sk_buff（内核网络包结构），把缓冲区的物理地址映射为内核可访问的虚拟地址；
- 把 sk_buff 交给上层协议栈（IP → TCP），后续由协议栈处理；
- 重新分配或回收缓冲区，更新描述符环，让网卡可以继续往新的缓冲区里 DMA 写数据。

### 5. 数据最终到达应用程序

协议栈处理完后，数据被拷贝到 socket 接收缓冲区，应用进程调用 `recv()` 时再从内核缓冲区拷贝到用户态缓冲区。注意：这一步的拷贝仍然由 CPU 完成，DMA 只负责了“网卡 → 内核内存”这一段。

## 关键点：DMA 到底省了什么

在这个例子里，如果没有 DMA，网卡收到帧后需要 CPU 逐字节/逐字地从网卡寄存器或 I/O 端口读取数据再写入内存，CPU 会被大量占用。有了 DMA，**“网卡缓冲区 → 内存”这段数据搬运由网卡硬件通过 PCIe 总线直接完成**，CPU 只在开始时配置描述符、结束时处理中断和协议栈，数据搬运本身零 CPU 参与。

这也解释了为什么 RDMA 能进一步优化：传统路径中 DMA 只覆盖了“网卡到内核内存”，之后还有内核协议栈处理、内核到用户态的拷贝；RDMA 网卡则通过 DMA 直接读写**应用程序的用户态内存**，并绕过内核协议栈，把 DMA 的能力延伸到了应用层。
