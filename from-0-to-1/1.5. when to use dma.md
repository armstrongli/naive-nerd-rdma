# 什么时候使用 DMA？

DMA 主要在**高带宽、大块数据传输**的场景下使用，核心判断标准是：用 DMA 带来的效率提升，是否值得它额外的配置开销。

## 主要使用场景

### 1. 高速外设的数据传输

这是 DMA 最典型的用武之地。对于磁盘（块设备）、网卡、显卡等设备，数据量动辄成百上千字节甚至整页、整帧，如果让 CPU 逐字搬运，算力会被严重浪费。DMA 允许这些设备直接与内存交换整块数据，CPU 只在传输开始前配置参数、传输结束后处理中断[citation:3][citation:11]。

### 2. 需要 CPU 与 I/O 并行工作的场合

DMA 的价值不只是“省搬运指令”，更在于**让 CPU 和 I/O 传输同时进行**。CPU 配置好 DMA 控制器后就可以去执行其他计算任务，数据搬运由硬件独立完成。对于嵌入式多核系统等场景，这种重叠计算与通信的能力尤其有用[citation:5]。

### 3. 网络数据包的接收与发送

网卡收到帧后，通过 DMA 直接写入驱动预先分配好的内存缓冲区；发送时同样由 DMA 从内存读取数据交给网卡。这正是你之前讨论的“网卡 DMA 写入内存”流程的应用场景[citation:2][citation:6]。

## 什么时候不一定用 DMA？

**小数据量或低带宽设备**：DMA 的配置本身有开销（设置源地址、目的地址、传输长度、启动控制器等）。如果只传几个字节，配置 DMA 的时间可能比 CPU 直接搬运还长。鼠标、键盘、麦克风这类低速设备通常用中断驱动或轮询就够了，不值得引入 DMA[citation:3]。具体“多大算大”取决于硬件，没有统一阈值，通常由驱动根据设备特性和传输大小来决定[citation:7]。
