# 应用直接操作的是专用 RDMA 网卡，而非普通网卡

**应用直接操作的网卡，是专用的 RDMA 网卡（RNIC），而不是普通以太网卡。**

你之前理解的“应用绕过内核直接和网卡打交道”，前提是这块网卡在硬件层面具备 RDMA 能力。普通网卡没有相应的硬件逻辑，无法独立完成 DMA 读写远端内存、维护队列对（QP）、处理 RDMA 协议头部等工作。

## 为什么必须是专用网卡？

专用 RDMA 网卡和普通网卡的本质区别在于**功能由谁执行**：

- **普通网卡**：只负责在物理链路上收发以太网帧。TCP/IP 协议栈的处理、内存拷贝、连接管理全部由主机 CPU 上的操作系统内核完成。
- **RDMA 网卡（RNIC）**：把协议处理、可靠传输、内存访问等原本由 CPU 承担的工作**卸载到了网卡硬件**上。它内置了处理引擎，能解析工作请求（WQE）、生成 RDMA 报文头、直接通过 DMA 读写应用注册的内存，全程不需要主机 CPU 介入数据路径。

正因为网卡硬件自己“会干活”，应用程序才能通过 `ibverbs` 接口直接把任务交给它，从而绕过内核。

## 几种主流 RDMA 网卡类型

根据你采用的 RDMA 技术路线，专用网卡也有所不同：

1. **InfiniBand 网卡**：专为 RDMA 设计的网络，性能最佳，但需要配套的专用交换机和网卡，不兼容标准以太网。
2. **RoCE 网卡（RoCEv2）**：在以太网上承载 RDMA，是目前数据中心最流行的方案。它**只需要端系统配备支持 RoCE 的专用网卡**，就可以利用标准以太网交换机进行通信。常见的有 NVIDIA Mellanox ConnectX 系列等。
3. **iWARP 网卡**：同样兼容以太网，但需要把整个 TCP/IP 协议栈卸载到硬件，实现复杂度和成本较高，部署不如 RoCE 广泛。

## 一个容易混淆的点：软件模拟

Linux 确实提供了软件模拟的 RDMA（如 `siw` 和 `rxe` 驱动），可以让普通网卡在测试场景中“跑”RDMA 协议。但需要注意，这种模式下 **RDMA 的核心优势并不存在**——数据搬运和协议处理仍然由主机 CPU 完成，只是接口上兼容 RDMA verbs。你之前讨论的“CPU 不参与数据拷贝”的硬件卸载效果，**只有真正的专用 RDMA 网卡才能实现**。
